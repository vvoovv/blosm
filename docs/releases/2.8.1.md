# Blosm 2.8.1

Blosm 2.8.1 is prepared for Blender 4.5 and newer, in Base and Pro editions.

## Google 3D Tiles through Cesium ion

With **Source: Google**, the new **Access via** option selects direct Google
access or Cesium ion. Direct Google remains the default. Add the corresponding
Google key or Cesium ion access token in addon preferences under **3D Tiles:**.
ArcGIS and Mapbox credentials are grouped under **Overlays:**.

Cesium ion access supports the existing blocking and progressive tile import
paths, concurrent downloads and joining. The ion token is visible in preferences.
Provider credentials remain in memory for the import and are redacted from
diagnostics. Other ion assets and automatic credential/session renewal during
an import are outside this release.

## Copyright information

Imports preserve and combine copyright notices and ion credits across imported
collections. Exact duplicates are displayed once. Copyright information is saved
in the blend file and follows Undo/Redo, including cancelled partial imports.

Deleted collections no longer contribute credits. Their stale registry entries
are removed during the next successful import. Renamed, hidden and unlinked
collections retain credits while their references remain valid. Older scene-wide
copyright text is preserved as legacy information.

## Interface

The **Source** and **Access via** label columns are wider so both labels fit at
the default sidebar width.

## Export texture paths

Pro's import-for-export renderer uses short intermediate compositor filenames
before moving images to their descriptive cache filenames. This avoids Windows
image-output path limits with nested data directories. Render cancellation,
missing/empty output, and unexpected extra files now produce explicit errors
instead of an index error. Deep-directory export and failure cleanup are covered
by the export test suite.

## Release qualification

The release test catalog includes headless ion/attribution checks for both Base
and Pro, plus explicit GUI checks. These checks use the installed candidate ZIP
when run under a build profile. This source preparation does not constitute a
new qualification run; release packages and test execution are deferred.
